# AXI-Lite PRNG (LFSR) ASIC Implementation using OpenROAD Flow

A complete **RTL-to-GDSII ASIC implementation** of an **AXI4-Lite based Pseudo Random Number Generator (PRNG)** using a **16-bit Linear Feedback Shift Register (LFSR)**. The project is implemented using the **SkyWater SKY130A Process Design Kit (PDK)** and a fully **open-source ASIC design flow**.

The implementation covers every major stage of digital ASIC design, beginning with RTL development and functional verification, followed by RTL lint checking, logic synthesis, physical design, static timing analysis, GDSII generation, and Design Rule Checking (DRC).

---

# Design Specifications

| Parameter | Description |
|-----------|-------------|
| **Protocol** | AXI4-Lite Slave Interface |
| **Random Number Generator** | 16-bit Linear Feedback Shift Register (LFSR) |
| **Technology** | SkyWater SKY130A |
| **Standard Cell Library** | sky130_fd_sc_hd |
| **Target Clock Frequency** | 100 MHz |
| **EDA Flow** | Open-Source RTL-to-GDSII |

# Design Flow

## 1. RTL Design

The design is developed in **Verilog HDL** and consists of the following modules:

- AXI-Lite Slave Interface
- 16-bit LFSR Core
- Top-Level Integration
- Testbench for Functional Verification

Functional simulation is performed before synthesis to verify the correctness of the RTL implementation.

---

## 2. RTL Simulation

The RTL is simulated using **Icarus Verilog** (or XSIM) to validate the functionality before synthesis.

Simulation verifies:

- AXI-Lite read/write transactions
- LFSR functionality
- Register operation
- Random number generation
- Functional correctness

---

## 3. RTL Lint Checking

RTL linting is performed using **Verilator** to detect coding issues before synthesis.

The lint process checks for:

- Syntax errors
- Width mismatches
- Undriven signals
- Unused signals
- Multiple drivers
- Inferred latches
- Coding style issues

Linting improves RTL quality and helps prevent downstream implementation problems.

---

## 4. Logic Synthesis (Yosys)

The RTL is synthesized using **Yosys**.

During synthesis:

- RTL elaboration
- Logic optimization
- Technology mapping
- Standard cell mapping using SKY130 library
- Gate-level netlist generation

Generated outputs include:

- Synthesized Verilog netlist
- Cell utilization report
- Area report
- Synthesis statistics

---

## 5. Physical Design (OpenROAD)

The synthesized gate-level netlist is imported into **OpenROAD** for complete physical implementation.

### Floorplanning

The floorplanning stage defines:

- Die area
- Core area
- Placement rows
- IO placement
- Power planning

A well-planned floorplan minimizes congestion and improves routing quality.

---

### Placement

Standard cells are placed inside the core area.

Placement optimization focuses on:

- Reducing wirelength
- Minimizing congestion
- Improving timing
- Legalizing standard cell placement

---

### Clock Tree Synthesis (CTS)

Clock Tree Synthesis distributes the clock signal across the design.

The objectives include:

- Reducing clock skew
- Minimizing insertion delay
- Balancing clock arrival time
- Improving timing performance

Clock buffers are automatically inserted during CTS.

---

### Routing

Routing connects all placed standard cells using the available metal layers.

Routing consists of:

- Global Routing
- Detailed Routing

The routing stage generates all physical interconnections while satisfying technology design rules.

---

### Finalization

The finalization stage performs several post-routing optimizations, including:

- Filler cell insertion
- Decap cell insertion
- Antenna repair
- Timing analysis
- Power analysis
- Area reporting
- DEF generation
- OpenROAD database generation

---

## 6. Static Timing Analysis (STA)

Static Timing Analysis is performed throughout the implementation flow.

Generated timing reports include:

- Setup Timing
- Hold Timing
- Worst Negative Slack (WNS)
- Total Negative Slack (TNS)
- Clock Skew Report

The objective is to achieve timing closure with no setup or hold violations.

---

## 7. GDSII Generation (Magic)

The final DEF generated by OpenROAD is imported into **Magic**.

Magic is used to:

- Generate the physical layout
- Export the final GDSII file
- Produce extracted layout views

The generated GDSII represents the manufacturable physical layout of the ASIC.

---

## 8. Design Rule Check (DRC)

The generated layout is verified using **Magic DRC**.

The DRC process checks compliance with SKY130 fabrication rules, including:

- Minimum spacing
- Minimum width
- Metal enclosure
- Via spacing
- Overlap rules
- Manufacturing constraints

The objective is to achieve a layout with **zero DRC violations**.
